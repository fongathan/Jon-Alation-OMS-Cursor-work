Workflow 1: Glossary Term Creation & Approval

Description: How a new business glossary term gets created, reviewed, and published in Alation.

Process Flow

1. Steward identifies need for new term

↓

2. Create term in Alation Glossary

↓

3. Add definition, synonyms, examples

↓

4. Approval required? → Yes: Submit for review → Governance approves → Publish

→ No: Publish directly

↓

5. Link term to tables/columns

↓

6. (Optional) Notify stakeholders

Step-by-Step Process

Step Actor Action Alation Location
1Data StewardIdentifies need for new term—
2Data StewardNavigates to Glossary in AlationGlossary tab / menu
3Data StewardClicks "Create Term"Glossary UI
4Data StewardEnters term name, definition, synonyms, examplesTerm form
5Data StewardSubmits for approval (if workflow enabled)Submit button
6Governance / LeadReviews and approves termApproval queue
7SystemTerm published—
8Data StewardLinks term to relevant tables/columnsAsset detail > Glossary
9Data Steward(Optional) Notifies domain usersEmail / Slack

Variations to Document:

  • ☐ Is approval required for all terms or only certain domains?
  • ☐ Who can create vs. approve terms?
  • ☐ Are there term templates or required fields?

OMS Requirements: Glossary creation UI; Approval workflow; Ability to link terms to tables/columns

Workflow 2: Data Discovery (Analyst Finding a Table)

Description: How an analyst typically searches for and evaluates a data asset before using it in a report or analysis.

Process Flow

1. Analyst has business question

↓

2. Search Alation — keyword or term

↓

3. Review search results → Found? No: Refine search / Browse by schema → back to step 2

↓ Yes

4. Open table/asset detail

↓

5. Review description, lineage, tags; check ownership, last updated

↓

6. (Optional) View sample data

↓

7. Use asset? Yes: Use in analysis / Add to favorites  |  No: Continue searching

Step-by-Step Process

Step Actor Action Alation Location
1AnalystHas business question or report need—
2AnalystEnters search (keyword, glossary term, table name)Search bar (global)
3AnalystReviews search results (tables, articles, glossary)Search results page
4AnalystIf not found, browses by datasource / schemaCatalog browse
5AnalystClicks on relevant table to open detailAsset detail page
6–9AnalystReads description, lineage, tags; checks ownership, usageOverview, Lineage, Tags tabs
10Analyst(Optional) Saves to favoritesFavorites / Saved

OMS Requirements: Global search; Asset detail with description, lineage, tags, ownership; Browse by datasource/schema; Favorites

Workflow 3: Metadata Stewardship (Tagging & Documentation)

Description: How a data steward adds or updates metadata (tags, description) on a catalog asset.

Process Flow

1. Steward identifies asset needing metadata

↓

2. Open asset in Alation → Add/edit description

↓

3. Apply tags (PII, domain, etc.)

↓

4. Link glossary terms if applicable

↓

5. Set ownership if unassigned

↓

6. Save changes → More assets? Repeat or Done

Step-by-Step Process

Step Actor Action Alation Location
1StewardIdentifies asset (from report, request, or backlog)—
2–3StewardNavigates to asset (search or browse), opens detailSearch / Catalog
4StewardClicks EditEdit button
5–8StewardAdds description, tags, glossary links, ownerDescription, Tags, Glossary, Owner fields
9StewardSaves changesSave button

OMS Requirements: Edit metadata on assets; Tag management; Glossary linking

Workflow 4: Impact Analysis (Engineer Assessing Change)

Description: How a data engineer uses lineage to assess impact before making a change to a table or pipeline.

Process Flow

1. Engineer plans to change table/pipeline

↓

2. Open asset in Alation

↓

3. View lineage — downstream

↓

4. Identify dependent tables, reports, dashboards

↓

5. Assess impact → Notify stakeholders if needed

↓

6. Proceed with change or defer

OMS Requirements: Lineage view (downstream, upstream); Table and ideally column-level lineage; Links to reports, dashboards, pipelines

Workflow 5: Compliance & Compliance Reporting

Description: How governance/compliance runs reports and ensures policy adherence in Alation.

Process Flow

1. Governance runs compliance report

↓

2. Open Policy Center or Reports → Select report type

↓

3. Run report / Export

↓

4. Review results → Identify gaps (untagged, unowned)

↓

5. Assign to stewards or escalate

↓

6. Track remediation → Re-run report for validation

OMS Requirements: Reporting on metadata coverage; Export capability; Policy/compliance reporting
