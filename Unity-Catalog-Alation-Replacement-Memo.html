Can Unity Catalog replace Alation?

Following Databricks Data + AI Summit 2026 (June 15–18), stakeholders are asking whether Unity Catalog (UC) can substitute for our in-house catalog on OMS. Short answer: no—UC is a strong Databricks governance layer, not an enterprise catalog replacement. We should continue OMS + Navigator and integrate UC as a governed metadata source.

Executive summary

Databricks announced meaningful UC advances at DAIS 2026: governed Metric Views, Domains (public preview), Unity AI Gateway, external lineage GA, and a Business Glossary announced as “preview coming soon”—not shipped. These strengthen lakehouse governance and agent context.

They do not deliver what Alation provides today: a cross-platform catalog with a stewarded business glossary, articles, bulk governance, and workflows for business users across Snowflake, pipelines, and BI—not only Databricks assets.

Recommendation: Continue the OMS + Navigator path for Alation exit (contract end October 1, 2026). Treat Unity Catalog as the execution-plane control for Databricks; ingest UC metadata into OMS so one search experience spans the estate.

What UC now does well

  • Metric Views — governed KPIs reusable in SQL, notebooks, Genie, dashboards
  • Domains (public preview) — business-area organization & marketplace browse
  • Unity AI Gateway (beta) — agent/model/MCP runtime governance
  • Trust signals: certifications, classification, ABAC, DQ monitoring
  • External lineage GA — metadata from outside Databricks
  • Governance Hub (private preview) — steward command center in Databricks

What UC does not replace

  • Business glossary — announced at DAIS 2026; preview coming soon (not GA)
  • Articles / document hubs — collaborative knowledge base
  • Enterprise-wide discovery — unified search across Snowflake, Airflow, Harmony, BI
  • Stewardship workflows — approvals, bulk edit, catalog sets at estate scale
  • Business-user UX — Navigator on OMS, not Catalog Explorer

Capability comparison (selected)

Recommended architecture

Hub-and-spoke: Unity Catalog governs Databricks execution; OMS federates the estate; Navigator is the business catalog experience.

  • One system of record per metadata type — avoid dual-writing glossary or PII tags in UC and OMS.
  • OMS + Navigator = enterprise catalog for Alation replacement.
  • Unity Catalog = source of truth for UC-managed schemas, permissions, lineage, metric views.
  • Sync UC → OMS so Databricks assets appear in the same search as Snowflake tables.

Leadership talking points

“Can we use UC instead of building in-house?”

UC improved for governed metrics and Databricks discovery, but not for business glossary, cross-platform catalog, or Alation-style stewardship. Right control plane inside Databricks; OMS + Navigator for Alation exit.

“Are we duplicating Databricks?”

Not if we integrate: UC = lakehouse governance; OMS = federated metadata store; Navigator = user experience. Same pattern industry uses with enterprise catalogs.

What to watch

  • UC Glossary (preview/GA) — evaluate ingestion into OMS, not a catalog pivot
  • Discover GA — useful for Databricks-heavy users only
  • BYOL maturity — weigh engineering cost vs OMS lineage supply
  • Metric Views in external BI — complements metrics governance
